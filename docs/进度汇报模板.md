# 爆单时刻 — 进度汇报模板

> 本文件用于向 AI 助手（Kimi）汇报开发进度。
> 请在完成每个 **Commit 节点** 或遇到 **阻塞** 时，复制下方对应模板填写并发送。

---

## 📋 汇报前检查清单

在汇报前，请确认：
- [ ] 代码已测试（能运行）
- [ ] 已提交 Git（`git status` 是干净的）
- [ ] 已推送远程（`git push` 已完成，可选但强烈建议）
- [ ] 截图/录屏已准备好（如有界面变化）

---

## 模板一：Commit 完成汇报（最常用）

当完成手册中的一个 Commit 节点时使用。

```
【检查点】Phase X - Commit Y: [Commit 描述，如"实现玩家移动和碰撞"]
【状态】✅ 完成

【运行证明】
（用文字描述当前能做什么，或附截图）
例：WASD 移动正常，角色不会穿墙，碰撞体大小合适。

【本次改动摘要】
- 新建文件：scripts/entities/player_character.gd
- 修改文件：project.godot（输入映射）
- 新建场景：scenes/entities/PlayerCharacter.tscn

【遇到的问题】（没有填"无"）
- 问题1：...
- 已尝试：...

【Git 状态】
最新 commit: [你的 commit message]
分支: main
```

## 模板二：Phase 验收汇报

当一个 Phase 的所有 Commit 完成，准备进入下一 Phase 时使用。

```
【检查点】Phase X 验收: [Phase 名称，如"核心循环"]
【状态】✅ 验收通过 / ⚠️ 部分通过（说明哪些未达标）

【验收对照】
对照手册验收标准逐项确认：
- [ ] 标准1：...
- [ ] 标准2：...
- [ ] 标准3：...

【演示说明】
（描述如何复现核心玩法，或附录屏）
例：打开 MainScene.tscn，按 F5 运行，WASD 移动角色到微波炉前，按空格放入料理包，等待3秒指示灯变红，按空格取出成品，走到顾客前按空格送餐，顾客5秒后吃完离开。

【已知问题 / 待办】
- 问题1：...
- 计划：放到 Phase Y 处理 / 立即修复

【Git 标签】
已打标签: git tag -a pX -m "Phase X 完成"
```

## 模板三：Bug / 阻塞求助

当卡壳超过 2 小时，或遇到无法解决的报错时使用。

```
【检查点】Phase X - 阻塞求助
【状态】❌ 阻塞

【问题描述】
（一句话说明发生了什么）
例：按空格交互时游戏崩溃，报错 Null instance 调用方法。

【报错信息】
（完整复制 Godot 的 Debugger 输出或控制台报错）
```
E 0:00:05:1234   player_character.gd:45
  试图在 null 实例上调用方法 'can_accept_item'
```

【相关代码】
（贴出出错的函数，不需要整个文件）
```gdscript
func try_interact() -> bool:
    var interactable := _get_interactable_object()
    if interactable.is_in_group("appliance"):
        return _interact_with_appliance(interactable)
```

【已尝试的解法】
- 尝试1：检查了场景树，确认 Microwave 有 "appliance" 组 → 无效
- 尝试2：... → 结果

【期望行为】
（描述你认为正确的行为应该是什么）
```

## 模板四：每日简报（可选，适合养成习惯）

当天工作结束时快速汇报，不需要每个 Commit 都发。

```
【检查点】每日简报 — 202X-XX-XX
【Phase】Phase X 进行中

【今日完成】
- Commit Y: ...
- Commit Z: ...

【明日计划】
- 完成 Commit A
- 开始 Commit B

【今日遇到的最大问题】
（没有填"无"）

【感受 / 想法】
（可选，比如"移动手感需要调整，感觉太慢了"）
```

---

## 🎯 汇报效率原则

1. **信息完整 > 格式完美**：哪怕不按模板，把关键信息给全就行
2. **贴代码要精简**：只贴出错的函数，不要贴整个文件（200行以上我会忽略）
3. **截图优先于文字**：有界面问题直接截图，比描述10句都清楚
4. **Git 是最强上下文**：告诉我 commit hash（`git log --oneline -1`），我可以基于那个版本给建议

---

## 快速命令速查

```bash
# 查看当前 Git 状态（汇报前执行）
git status

# 查看最近的提交历史（汇报时复制）
git log --oneline -5

# 查看当前分支和最近的改动
git branch && git diff --stat

# 给当前 Phase 打标签（Phase 验收后执行）
git tag -a p1 -m "Phase 1 完成：核心循环可运行"
git push origin p1
```
