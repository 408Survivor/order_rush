## 1. 项目约定与开发原则

### 1.1 核心理念：先能跑，再跑好

作为初学者，你的第一优先级是**在两周内做出一个能按空格键运行的东西**。不要追求完美的架构，但要追求**干净的项目结构**。结构健康，后期重构成本低；结构混乱，两周后你自己都找不到代码在哪。

### 1.2 项目目录结构（严格执行）

```
order_rush/
├── .git/                  # Git 版本控制（必须）
├── .gitignore             # 忽略规则（见下方模板）
├── project.godot          # Godot 项目文件
├── README.md              # 项目说明（至少包含：如何运行、当前Phase、已知问题）
│
├── scenes/                # 所有 .tscn 场景文件
│   ├── levels/            # 关卡/日场景
│   ├── entities/          # 游戏实体（玩家、顾客、设备）
│   ├── ui/                # UI 场景（如非独立脚本）
│   └── props/             # 道具/环境物件
│
├── scripts/               # 所有 .gd 脚本文件
│   ├── autoload/          # 自动加载（单例）
│   ├── entities/          # 实体行为脚本
│   ├── systems/           # 游戏系统（订单、经济、时间）
│   ├── ui/                  # UI 逻辑脚本
│   └── utils/             # 工具函数（尽量少，Godot内置足够）
│
├── assets/                # 所有资源文件
│   ├── art/
│   │   ├── characters/    # 角色图
│   │   ├── items/         # 物品/料理包图
│   │   ├── environment/   # 店铺背景、地板、墙壁
│   │   ├── ui/            # UI 素材、图标
│   │   └── effects/       # 粒子、光效（Phase 3+）
│   ├── audio/
│   │   ├── bgm/           # 背景音乐
│   │   ├── sfx/           # 音效（ cooking, pickup, alert 等）
│   │   └── ambience/      # 环境音（Phase 3+）
│   └── fonts/             # 字体文件
│
├── resources/             # Godot 资源（如 .tres 材质、自定义数据）
│   ├── data/              # 游戏数据（菜品配置、角色配置等）
│   └── themes/            # UI 主题资源
│
└── docs/                  # 设计文档（非代码，但纳入版本控制）
    ├── gdd/               # 游戏设计文档
    └── prompts/           # AI 美术提示词备份
```

**🚨 铁律**：
- `.tscn` 文件**只能**出现在 `scenes/` 及其子目录中。
- `.gd` 文件**只能**出现在 `scripts/` 及其子目录中。
- `.png`, `.jpg`, `.svg` **只能**出现在 `assets/art/` 中。
- `.mp3`, `.ogg`, `.wav` **只能**出现在 `assets/audio/` 中。
- 根目录**禁止**出现任何资源文件或脚本。

### 1.4 命名规范（严格执行）

| 类型 | 规范 | 示例 |
|------|------|------|
| 场景文件 | PascalCase | `MainScene.tscn`, `Microwave.tscn`, `MainScene.tscn` |
| 脚本文件 | snake_case | `player_character.gd`, `order_manager.gd`, `microwave.gd` |
| 脚本内变量 | snake_case | `current_order`, `heat_timer`, `is_occupied` |
| 信号 | 过去分词/动宾结构 | `order_completed`, `item_picked_up`, `microwave_started` |
| 常量 | UPPER_SNAKE_CASE | `MAX_ORDERS = 5`, `MICROWAVE_HEAT_TIME = 3.0` |
| 节点名 | PascalCase | `PlayerSprite`, `CollisionShape2D`, `TimerHeat` |
| 函数 | snake_case | `process_order()`, `can_interact()` |
| 枚举 | PascalCase（类型），成员 UPPER_SNAKE_CASE | `OrderStatus.PENDING`, `OrderStatus.COMPLETED` |
| 资源文件 | snake_case | `dish_data.toml`（或 .gd 的 @export 配置） |

### 1.5 代码注释规范

每个脚本文件顶部必须包含：

```gdscript
## 文件: scripts/entities/player.gd
## 职责: 玩家角色的移动、交互和手持物品管理
## 依赖: InputManager（autoload）、OrderManager（autoload）
## 作者: 你的名字
## 创建日期: 2026-07-05
```

每个函数注释：

```gdscript
## 尝试与当前面对的交互对象交互
## 输入: 无（依赖当前 facing_direction 和 interaction_ray）
## 输出: bool（是否成功触发交互）
## 副作用: 可能修改 held_item、触发设备状态变化
func try_interact() -> bool:
    ...
```

### 1.6 禁止魔法数字

所有数值必须是常量或 @export 变量：

```gdscript
# ❌ 错误
await get_tree().create_timer(3.0).timeout

# ✅ 正确
const MICROWAVE_HEAT_TIME := 3.0  # 秒
await get_tree().create_timer(MICROWAVE_HEAT_TIME).timeout
```

```gdscript
# 更好的做法：允许设计师在编辑器中调整
@export var microwave_heat_time: float = 3.0
```

### 详细周计划

#### Week 1: Phase 0 — 美术风格锁定

**Day 1-2: 风格探索**

  1. 玩家角色（俯视角，站立，手持物品姿态）

  3. 料理包（俯视角，扁平，1-2种）
  4. 成品菜（装盘，俯视角）

**Day 7: 验收与Commit**

## 3. Phase 0: 美术风格锁定

### 3.1 执行步骤

**Step 1: 收集参考图（2小时）**

在 Pinterest/小红书/游戏截图中收集以下类别的参考：
- 飞机大厨：UI布局、食物摆放方式、顾客形象
- 杯杯倒满：角色比例、店铺俯视角、色彩饱和度
- 扁平插画：2-3个你最喜欢的独立游戏美术风格（如《Spiritfarer》《Overcooked》）

将这些参考图放入 `docs/ref_images/`（自己创建，不纳入Git，但保留）。

**Step 2: 编写风格基准Prompt（1小时）**

从参考图中提炼出**3-5个核心视觉关键词**，例如：
- "top-down perspective"（俯视角）
- "flat vector illustration"（扁平矢量插画）
- "warm saturated colors"（暖色高饱和）
- "chibi proportion, big head small body"（Q版比例）
- "clean bold outlines"（清晰粗描边）

将这些关键词组合成**风格基准句**：

```
Top-down perspective, flat vector illustration, warm saturated colors, 
chibi proportion with big head and small body, clean bold outlines, 
2D game asset, transparent background, single object centered, 
no text, no watermark
```

**Step 3: 批量生成测试（3-4小时）**

用上述基准句 + 具体对象描述，在豆包/可灵/即梦中生成。推荐工具：
- **即梦**：生成游戏 asset 最稳定，支持透明背景
- **豆包**：速度快，适合快速迭代
- **可灵**：角色一致性较好

**Step 4: 筛选与统一（2小时）**

将生成的图按以下标准筛选：
1. 风格一致（所有图看起来像是同一款游戏）
2. 透视统一（都是俯视角，角度一致）
3. 比例协调（角色和家具的比例合理）
4. 背景干净（透明或纯色，便于裁剪）

**Step 5: 导入Godot（1小时）**

按1.2节的目录结构放入，并设置 Filter。

### 3.3 Godot 导入规范

1. 将图片放入 `assets/art/` 对应子目录
2. 在 Godot 的 **FileSystem** 面板中，选中图片
3. 在 **Import** 标签中：
   - **Filter**: 选择 `Nearest`（保留像素/扁平风格的锐利边缘）
   - 如果图片很大，考虑 **Size Limit** 设为 1024 或 2048
4. 点击 **Reimport**（如果已经导入过，需要点击 **Reimport** 按钮）
5. 创建 **Sprite2D** 节点测试显示效果

**重要**：如果图片不是透明背景（PNG），而是在白色背景上，需要：
- 在 Photoshop/GIMP/在线工具中去除背景
- 或使用 Godot 的 **CanvasItem → Material → New ShaderMaterial** 做简单抠图（不推荐，最好预处理）

## 4. Phase 1: 核心循环实现

### 4.1 本阶段目标（明确边界）

**必须实现**：
- 玩家角色在场景中WASD移动
- 玩家可以拿起/放下料理包（一次一件）
- 玩家可以把料理包放入微波炉，按空格启动加热
- 微波炉加热3秒后完成，玩家取出成品
- 成品可以放到顾客面前（顾客会自动出现并等待）
- 顾客吃完后离开，订单完成

**明确不做**（避免过度工程）：
- ❌ 多菜品（只做1种L1菜品）
- ❌ 外卖系统
- ❌ 经济系统（不做钱）
- ❌ 耐心值/评分
- ❌ 多关卡/存档
- ❌ 音效（除调试外）
- ❌ 粒子效果
- ❌ 多角色选择

### 4.3 场景树节点设计

```gdscript
## 文件: scripts/autoload/GameStateManager.gd
## 职责: 全局游戏状态管理，Phase 1仅维护订单状态
## 依赖: 无
## 注意: 后续阶段会扩展为包含经济、天数、角色等状态

extends Node

# ==================== 信号 ====================
## 当订单状态变化时发出（供UI和调试面板监听）
signal order_state_changed(order_id: int, new_state: int)

# ==================== 常量 ====================
const MAX_CONCURRENT_ORDERS := 1  # Phase 1 只支持1单

# ==================== 枚举 ====================
enum OrderState {
    PENDING,    ## 等待制作
    COOKING,    ## 制作中
    READY,      ## 制作完成，等待送餐
    SERVED,     ## 已送达，顾客用餐中
    COMPLETED,  ## 顾客吃完，订单完成
    FAILED      ## 超时或失败（Phase 2启用）
}

# ==================== 状态变量 ====================
## 当前活跃订单列表
## 结构: [{ id: int, state: OrderState, customer_id: int, dish_type: String }]
var active_orders: Array[Dictionary] = []

var _next_order_id := 1

# ==================== 订单管理 ====================

## 生成一个新订单
## 输入: customer_id (int), dish_type (String)
## 输出: int (order_id)
## 副作用: 添加订单到 active_orders，发出 order_state_changed
func create_order(customer_id: int, dish_type: String) -> int:
    if active_orders.size() >= MAX_CONCURRENT_ORDERS:
        push_warning("Max concurrent orders reached, cannot create new order")
        return -1
    
    var order_id := _next_order_id
    _next_order_id += 1
    
    var order := {
        "id": order_id,
        "state": OrderState.PENDING,
        "customer_id": customer_id,
        "dish_type": dish_type,
        "created_at": Time.get_time_dict_from_system()
    }
    active_orders.append(order)
    order_state_changed.emit(order_id, OrderState.PENDING)
    
    print_rich("[color=green]Order %d created: %s[/color]" % [order_id, dish_type])
    return order_id


## 更新订单状态
## 输入: order_id (int), new_state (OrderState)
## 输出: bool (是否成功更新)
## 副作用: 修改订单状态，发出 order_state_changed
func update_order_state(order_id: int, new_state: int) -> bool:
    for order in active_orders:
        if order["id"] == order_id:
            var old_state := order["state"] as int
            order["state"] = new_state
            order_state_changed.emit(order_id, new_state)
            
            print_rich("[color=yellow]Order %d: %s -> %s[/color]" % [
                order_id, 
                OrderState.keys()[old_state],
                OrderState.keys()[new_state]
            ])
            return true
    
    push_warning("Order %d not found" % order_id)
    return false


## 获取指定订单
## 输入: order_id (int)
## 输出: Dictionary (订单数据，找不到返回空字典)
func get_order(order_id: int) -> Dictionary:
    for order in active_orders:
        if order["id"] == order_id:
            return order
    return {}


## 移除已完成/失败的订单
## 输入: order_id (int)
## 输出: bool (是否成功移除)
func remove_order(order_id: int) -> bool:
    for i in range(active_orders.size()):
        if active_orders[i]["id"] == order_id:
            active_orders.remove_at(i)
            print_rich("[color=gray]Order %d removed[/color]" % order_id)
            return true
    return false


## 获取当前活跃订单数量
func get_active_order_count() -> int:
    return active_orders.size()


# ==================== 调试辅助 ====================

## 返回所有订单的可读状态字符串
func get_orders_debug_string() -> String:
    var result := "Active Orders: %d\n" % active_orders.size()
    for order in active_orders:
        result += "  #%d: %s (%s)\n" % [
            order["id"],
            OrderState.keys()[order["state"]],
            order["dish_type"]
        ]
    return result
```

## 文件: scripts/entities/player_character.gd
## 职责: 玩家角色控制、移动、交互、手持物品管理
## 依赖: GameStateManager (autoload)
## 注意: 这是游戏最核心的脚本，保持简洁，避免过度功能

extends CharacterBody2D

# ==================== 常量 ====================
const MOVE_SPEED := 200.0           ## 像素/秒，移动速度
const INTERACTION_DISTANCE := 32.0  ## 交互检测距离（像素）
const INTERACTION_COOLDOWN := 0.3   ## 交互冷却时间（秒），防止连按

# ==================== 导出变量（可在编辑器调整） ====================
@export var move_speed: float = MOVE_SPEED
@export var interaction_distance: float = INTERACTION_DISTANCE

# ==================== 节点引用 ====================
@onready var sprite: Sprite2D = $Sprite2D
@onready var interaction_ray: RayCast2D = $InteractionRay
@onready var held_item_pivot: Marker2D = $HeldItemPivot

# ==================== 状态变量 ====================
## 当前手持物品（Node2D 子类，如 MealPackage 或 FinishedDish）
var held_item: Node2D = null

## 面对方向（用于交互检测和Sprite翻转）
var facing_direction := Vector2.DOWN

## 交互冷却计时器
var _interaction_cooldown := 0.0

## 输入轴（缓存，避免每帧重新计算）
var _input_vector := Vector2.ZERO

# ==================== 生命周期 ====================

func _ready() -> void:
    ## 设置玩家组标签，方便其他系统查找
    add_to_group("player")
    
    ## 确保交互射线初始方向正确
    interaction_ray.target_position = facing_direction * interaction_distance
    print_rich("[color=green]Player ready at %s[/color]" % str(global_position))


func _process(delta: float) -> void:
    ## 更新冷却计时器
    if _interaction_cooldown > 0:
        _interaction_cooldown -= delta


func _physics_process(delta: float) -> void:
    ## 读取输入
    _read_input()
    
    ## 计算移动速度
    velocity = _input_vector * move_speed
    
    ## 执行移动（Godot内置碰撞处理）
    move_and_slide()
    
    ## 更新面向方向（用于交互检测）
    if _input_vector != Vector2.ZERO:
        facing_direction = _input_vector.normalized()
        _update_sprite_direction()
    
    ## 更新交互射线方向
    interaction_ray.target_position = facing_direction * interaction_distance


# ==================== 输入处理 ====================

func _input(event: InputEvent) -> void:
    ## 检测交互按键（空格或E）
    if event.is_action_pressed("interact"):
        try_interact()


## 读取WASD/方向键输入，归一化向量
func _read_input() -> void:
    _input_vector = Input.get_vector(
        "move_left", "move_right", "move_up", "move_down"
    )


## 根据移动方向更新Sprite朝向
func _update_sprite_direction() -> void:
    ## 简单处理：左右翻转
    if facing_direction.x < 0:
        sprite.flip_h = true
    elif facing_direction.x > 0:
        sprite.flip_h = false
    
    ## 未来可扩展：根据上下方向切换不同的Sprite帧

# ==================== 交互系统 ====================

## 尝试与前方对象交互
## 这是核心交互逻辑：
## 1. 如果有手持物品，尝试将其交给/放置到目标
## 2. 如果没有手持物品，尝试从目标拾取
## 3. 如果目标是设备（如微波炉），尝试启动/操作
func try_interact() -> bool:
    ## 检查冷却
    if _interaction_cooldown > 0:
        return false
    _interaction_cooldown = INTERACTION_COOLDOWN
    
    ## 获取交互射线检测到的对象
    var interactable := _get_interactable_object()
    if interactable == null:
        print_debug("No interactable object in front")
        return false
    
    print_debug("Interacting with: %s" % interactable.name)
    
    ## 根据对象类型执行不同交互
    if interactable.is_in_group("storage"):
        return _interact_with_storage(interactable)
    elif interactable.is_in_group("appliance"):
        return _interact_with_appliance(interactable)
    elif interactable.is_in_group("customer"):
        return _interact_with_customer(interactable)
    elif interactable.is_in_group("pickable"):
        return _interact_with_pickable(interactable)
    
    return false


## 获取交互射线命中的可交互对象
func _get_interactable_object() -> Node2D:
    if interaction_ray.is_colliding():
        var collider := interaction_ray.get_collider()
        if collider != null and collider.is_in_group("interactable"):
            return collider
    return null


## 与储物设备交互（如冰柜，取料理包）
func _interact_with_storage(storage: Node2D) -> bool:
    if held_item != null:
        print_debug("Hands full, cannot take from storage")
        return false
    
    var item := storage.give_item()
    if item != null:
        _pick_up_item(item)
        return true
    return false


## 与设备交互（如微波炉）
func _interact_with_appliance(appliance: Node2D) -> bool:
    ## 如果手持物品，尝试放入
    if held_item != null:
        if appliance.can_accept_item(held_item):
            var item := held_item
            _drop_item()
            appliance.accept_item(item)
            return true
    ## 如果空手，尝试取出
    else:
        var item := appliance.give_item()
        if item != null:
            _pick_up_item(item)
            return true
    
    return false


## 与顾客交互（送餐）
func _interact_with_customer(customer: Node2D) -> bool:
    if held_item == null:
        return false
    
    ## 检查顾客是否等待这盘菜
    if customer.can_accept_dish(held_item):
        var dish := held_item
        _drop_item()
        customer.receive_dish(dish)
        return true
    
    return false


## 与可拾取物品交互（地上的料理包/成品）
func _interact_with_pickable(pickable: Node2D) -> bool:
    if held_item != null:
        print_debug("Hands full, cannot pick up %s" % pickable.name)
        return false
    
    _pick_up_item(pickable)
    return true

# ==================== 手持物品管理 ====================

## 拾取物品到手
## 输入: item (Node2D) - 必须是可手持物品
## 副作用: 将物品设为当前节点的子节点，移动到 held_item_pivot
func _pick_up_item(item: Node2D) -> void:
    if held_item != null:
        push_warning("Already holding an item, cannot pick up another")
        return
    
    held_item = item
    
    ## 将物品从原父节点移出，挂到玩家身上
    if item.get_parent() != null:
        item.get_parent().remove_child(item)
    
    held_item_pivot.add_child(item)
    item.position = Vector2.ZERO
    item.scale = Vector2.ONE * 0.8  ## 手持时稍微缩小
    
    print_rich("[color=cyan]Picked up: %s[/color]" % item.name)


## 放下当前手持物品到地上
## 输出: Node2D (被放下的物品，空手时返回null)
func _drop_item() -> Node2D:
    if held_item == null:
        return null
    
    var item := held_item
    held_item = null
    
    ## 从玩家身上移出，放到场景中
    if item.get_parent() != null:
        item.get_parent().remove_child(item)
    
    ## 添加到场景的 Items 层（假设 MainScene 有 Items 节点）
    var items_layer := get_tree().current_scene.get_node_or_null("Items")
    if items_layer != null:
        items_layer.add_child(item)
        item.global_position = global_position + facing_direction * 20
    else:
        ## 兜底：直接加到当前场景
        get_tree().current_scene.add_child(item)
        item.global_position = global_position + facing_direction * 20
    
    item.scale = Vector2.ONE
    
    print_rich("[color=orange]Dropped: %s[/color]" % item.name)
    return item


## 返回当前手持物品类型（用于调试和UI显示）
func get_held_item_type() -> String:
    if held_item == null:
        return "empty"
    return held_item.name


# ==================== 调试辅助 ====================

func print_debug(msg: String) -> void:
    print_rich("[Player] %s" % msg)

    eat_timer.timeout.connect(_on_eat_timer_timeout)


func _physics_process(delta: float) -> void:
    match current_state:
        CustomerState.ENTERING:
            _process_entering(delta)
        CustomerState.LEAVING:
            _process_leaving(delta)
        ## WAITING 和 EATING 状态不移动

# ==================== 状态处理 ====================

## 进入店铺，走向座位
func _process_entering(delta: float) -> void:
    if target_seat == null:
        return
    
    var direction := (target_seat.global_position - global_position).normalized()
    velocity = direction * move_speed
    move_and_slide()
    
    ## 检查是否到达座位
    if global_position.distance_to(target_seat.global_position) < 5.0:
        _on_seated()


## 离开店铺
func _process_leaving(delta: float) -> void:
    var direction := (exit_position - global_position).normalized()
    velocity = direction * move_speed
    move_and_slide()
    
    ## 检查是否到达出口
    if global_position.distance_to(exit_position) < 5.0:
        _on_left_shop()


## 顾客坐下
func _on_seated() -> void:
    current_state = CustomerState.WAITING
    velocity = Vector2.ZERO
    seated.emit()
    
    ## 创建订单
    current_order_id = GameStateManager.create_order(get_instance_id(), expected_dish_type)
    order_placed.emit(expected_dish_type)
    
    print_rich("[color=green]Customer seated, order #%d placed[/color]" % current_order_id)


## 顾客离开店铺
func _on_left_shop() -> void:
    left_shop.emit()
    
    ## 清理订单
    if current_order_id >= 0:
        GameStateManager.remove_order(current_order_id)
    
    queue_free()  ## 销毁顾客节点

# ==================== 交互接口 ====================

## 检查是否可以接受某盘菜
## 输入: dish (Node2D)
## 输出: bool
func can_accept_dish(dish: Node2D) -> bool:
    ## 必须处于等待状态
    if current_state != CustomerState.WAITING:
        return false
    ## 必须是成品菜
    if not dish.is_in_group("finished_dish"):
        return false
    return true


## 接收菜品
## 输入: dish (Node2D)
## 输出: bool（是否成功接收）
func receive_dish(dish: Node2D) -> bool:
    if not can_accept_dish(dish):
        return false
    
    ## 销毁菜品（简化：顾客直接"吃"掉）
    ## 后续阶段可以保留菜品在桌上
    dish.queue_free()
    
    current_state = CustomerState.EATING
    eat_timer.start()
    
    ## 更新订单状态
    if current_order_id >= 0:
        GameStateManager.update_order_state(current_order_id, GameStateManager.OrderState.SERVED)
    
    dish_received.emit()
    print_rich("[color=green]Customer started eating[/color]")
    
    return true


## 用餐计时器超时
func _on_eat_timer_timeout() -> void:
    if current_state != CustomerState.EATING:
        return
    
    current_state = CustomerState.LEAVING
    
    ## 更新订单状态
    if current_order_id >= 0:
        GameStateManager.update_order_state(current_order_id, GameStateManager.OrderState.COMPLETED)
    
    finished_eating.emit()
    print_rich("[color=green]Customer finished eating, leaving[/color]")


# ==================== 初始化 ====================

## 设置顾客的座位和出口
func setup(spawn_pos: Vector2, seat: Marker2D, exit: Vector2) -> void:
    global_position = spawn_pos
    target_seat = seat
    exit_position = exit


# ==================== 调试辅助 ====================

func get_debug_info() -> String:
    return "Customer: %s | Order: #%d | Dish: %s" % [
        CustomerState.keys()[current_state],
        current_order_id,
        expected_dish_type
    ]

## 5. Git 提交规范与节点

### 5.1 Commit Message 规范

使用 **Conventional Commits** 简化版：

```
<type>: <简短描述>

<可选的详细描述>
```

**类型（type）**：
- `feat`: 新功能
- `fix`: 修复Bug
- `docs`: 文档更新
- `style`: 格式调整（不影响代码逻辑）
- `refactor`: 重构
- `chore`: 构建/工具/配置变动
- `asset`: 美术/音频资源更新

**示例**：
```
feat: 实现玩家移动和基础交互

- WASD 移动，带碰撞检测
- 空格键交互，面向方向检测
- 手持物品系统（一次一件）

feat: 实现微波炉加热逻辑

- 放入料理包，启动3秒加热
- 加热完成后变为成品菜
- 状态指示灯（绿/黄/红）

asset: 添加微波炉和料理包美术素材

- 使用AI生成，扁平插画风
- 设置Filter为Nearest
```

### 5.3 Git 工作流建议

**日常操作**：

## 6. 常见坑与陷阱

### 6.1 文件管理类

| 坑 | 后果 | 预防 |
|----|------|------|
| 在根目录放文件 | 项目膨胀后找不到东西 | 严格执行目录结构，每天检查 |
| 场景和脚本同名但不同位置 | 误以为是一体的，改了一个忘了另一个 | 用 `scenes/` 和 `scripts/` 前缀思考 |
| 图片不改Filter | 扁平风格变模糊 | 导入后立刻检查Filter设置 |
| 资源文件中文命名 | 某些平台导出失败 | 全部使用英文 snake_case 命名 |
| 不清理未使用资源 | 项目体积膨胀，加载慢 | 每周检查并删除无用文件 |

### 6.2 Git 使用类

| 坑 | 后果 | 预防 |
|----|------|------|
| 忘记 .gitignore | 提交大量临时文件，仓库膨胀 | 项目第一天就配置好 |
| 长时间不提交 | 丢失大量工作（崩溃/误删） | 每完成一个小功能就提交 |
| 不推送到远程 | 本地硬盘损坏=项目消失 | 每天结束推送到GitHub/Gitee |
| Commit message 随意 | 找不到某个改动在哪 | 使用规范格式，写清楚做了什么 |
| 直接改main分支 | 无法回退，新功能破坏旧功能 | 功能分支开发（进阶） |

### 6.3 Godot 新手类

| 坑 | 后果 | 预防 |
|----|------|------|
| 用 _process 做物理移动 | 移动卡顿，碰撞穿透 | 物理移动放 _physics_process |
| 每帧 get_node() | 性能下降，代码冗余 | 用 @onready 缓存节点引用 |
| 信号不连接 | 事件不触发，功能失效 | 在 _ready 中检查信号连接 |
| 不使用组（Group） | 查找对象困难，代码耦合 | 善用 add_to_group |
| 场景实例化后忘记 add_child | 对象不显示，找不到原因 | 实例化后立刻 add_child |
| 在编辑器改了节点名但代码没改 | 空引用崩溃 | 改名后全局搜索旧名 |
| 不使用类型注解 | 类型错误难排查 | 尽可能用 `->` 标注返回类型 |
| 自己写计时器 | 容易出bug，Godot Timer更稳定 | 优先用 Timer 节点 |
| 全局变量满天飞 | 状态管理混乱，调试困难 | 用 Autoload 单例集中管理 |
| 过早优化 | 为不存在的问题写复杂代码 | 先跑起来，再profile优化 |

### 6.4 游戏设计类

| 坑 | 后果 | 预防 |
|----|------|------|
| 第一阶段做太多功能 | 两个月没做出可玩的 | 严格遵守Phase边界，不做计划外功能 |
| 数值凭感觉 | 游戏太简单或太难 | 把数值做成 @export，方便实时调整测试 |
| 忽视操作手感 | 游戏玩起来很"飘" | 花时间调整移动速度、加速度、交互距离 |
| 没有反馈 | 玩家不知道发生了什么 | 每个操作都要有视觉/听觉反馈（哪怕是最简单的） |
| 过早做存档系统 | 增加复杂度，数据格式频繁变 | Phase 5 后再做持久化 |

## 结语

这份手册是你开发"爆单时刻"的路线图。记住以下优先级：

1. **结构 > 代码质量 > 功能数量** — 先把文件放对位置，再写干净的代码，最后才加功能
2. **两周内要有可运行的东西** — 不要完美主义，Phase 1能按空格加热食物就是胜利
3. **每天提交Git** — 这是你的时光机，比任何代码都重要
4. **不要提前做后面的Phase** — 看到好想法先记到 `docs/ideas.md`，不急着实现

祝开发顺利！🎮
