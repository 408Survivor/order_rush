## 2. 设计决策

- **游戏定位**（既有文档）：2D 俯视角预制菜小餐馆经营模拟，融合《飞机大厨》高频操作爽感与《杯杯倒满》PC 键盘经营深度。
- **阶段规划 P0–P9**（进度看板）：P0 美术风格锁定 / P1 核心循环 / P2 订单系统 / P3 经济系统 / P4 外卖系统 / P5 设备升级 / P6 卡牌系统 / P7 多菜品+难度 / P8 角色系统 / P9 Polish；总里程碑 12–16 周。
- **P1 核心循环验收标准**（进度看板，本对话开始逐项实现）：
  - WASD 移动流畅、有碰撞 ✅（本次完成）
  - 空格键交互（取/放/加热）⏳（本次交付代码，未验证）
  - 手持物品系统：一次只能拿一件，放下后在地面上 ⏳
  - 微波炉：放入料理包 → 加热 3 秒 → 指示灯变化 → 取出成品（未开始）
  - 顾客：生成 → 入座 → 等待 → 收到菜 → 吃 5 秒 → 离开（未开始）
- **订单系统数值**（AI 写入 `GameStateManager.gd`，按手册 Phase 1 简化）：`MAX_CONCURRENT_ORDERS := 1`（P1 只支持 1 单）；`OrderState` 枚举：PENDING / COOKING / READY / SERVED / COMPLETED / FAILED（FAILED 标注 Phase 2 启用）。
- **玩家数值**（AI 建议并写入脚本）：`MOVE_SPEED := 200.0` 像素/秒；`INTERACTION_RADIUS := 80.0` 像素；`INTERACTION_COOLDOWN := 0.3` 秒；手持物品挂点 `HeldItemPivot` 的 `y = -40`（物品显示在厨师头顶）；`InteractionArea` 用 CircleShape2D、半径约 60 像素、Collision 设 **Layer 3（Interactables）**；玩家 `_ready()` 中 `add_to_group("player")`。
- **美术风格**：扁平插画风、俯视角；AI 生成工具为即梦 5.0 Lite（风格已锁定）；有效提示词结构 `Overhead view, bird eye view from directly above, [主体描述], [统一风格后缀]`。【前序 Session 用户决定】
- **导入/渲染决策**：纹理过滤用 **Nearest** 保持锐利边缘（非 Linear、非 Nearest Mipmap）；导入预设 Texture2D、压缩 Lossless、启用「修复 Alpha 边框」。因 Godot 4 的 Texture2D 导入面板没有 Filter 选项，改为在 `project.godot` 全局设置 `textures/canvas_textures/default_texture_filter=0`（0 = Nearest）。【AI 建议并实施】
- **输入映射**（AI 预设在 project.godot，用户在编辑器中确认）：`move_left` A/←、`move_right` D/→、`move_up` W/↑、`move_down` S/↓（deadzone 0.5）、`interact` 空格/E、`debug_toggle` F1。

## 3. 技术细节

- **实际运行环境**（用户贴出的运行日志）：`Godot Engine v4.7.stable.official.5b4e0cb0f`，Apple M1（arm64），Metal 4.0 - **Forward Mobile** 渲染器。注意：开发手册与 project.godot features 写的是 `4.4`，实际装的是 4.7，存在版本口径不一致。
- **Godot 安装**（AI 建议、用户执行）：官网下载 macOS **ARM64** 标准版（蓝色按钮「Godot Engine 4.7」），**不选 .NET 版**（项目纯 GDScript，.NET 版体积大且无必要）；解压后拖入「应用程序」；首次打开需在 系统设置 → 隐私与安全性 点「仍要打开」。
- **project.godot 关键配置**（AI 写入）：
  - `config/name="Order Rush"`，描述「2D 俯视角预制菜小餐馆经营模拟游戏」，tags `("2d","simulation","cooking")`
  - `run/main_scene="res://scenes/MainScene.tscn"`
  - `config/features=PackedStringArray("4.4", "Mobile")`
  - autoload：`GameStateManager="*res://scripts/autoload/GameStateManager.gd"`
  - 窗口 `1280x720`，`stretch/mode="canvas_items"`、`stretch/aspect="expand"`
  - `[debug] gdscript/warnings/return_value_discarded=0`
  - `[rendering] textures/canvas_textures/default_texture_filter=0`
- **场景结构**：
  - `scenes/MainScene.tscn`：用户先在 Godot 里建 `TestScene.tscn`（Node2D 根 + Sprite2D），后自行重命名为 `MainScene.tscn` 以匹配主场景配置；AI 后续删掉了其中残留的独立 Sprite2D，只保留 `PlayerCharacter` 实例。
  - `scenes/entities/PlayerCharacter.tscn`：`CharacterBody2D` 根节点 + `Sprite2D`（厨师图，Scale 0.2/0.2）+ `CollisionShape2D`（CircleShape2D）。后续手持物品系统要求再加 `Marker2D(HeldItemPivot)` 和 `Area2D(InteractionArea)`。
- **关键坑与修复**（本次实战记录，均为 AI 诊断、用户验证）：
  1. **显示只有一角/白底**：AI 生成图约 1024×1024，大于 1280×720 视口 → Sprite2D Scale 改 0.2；`centered=false` 时图片从左上角绘制，用户关闭 centered 后完整显示（但厨师图实为白底非透明，记为素材已知问题）。
  2. **运行崩溃/角色不动**：`project.godot` 配了 GameStateManager autoload 但文件不存在 → AI 补建 `scripts/autoload/GameStateManager.gd`（extends Node，订单状态机 + `order_state_changed(order_id, new_state)` 信号 + `create_order(customer_id, dish_type)`）。
  3. **创建脚本 ≠ 附加脚本**：用户在 Godot 里创建了 `player_character.gd` 但没绑定到节点；用户自己发现并把脚本**拖到 PlayerCharacter 节点上**才生效。【用户发现】
  4. **A/D 翻转瞬移**：`centered=false` 时锚点在左上角，脚本用 `scale.x = ±0.2` 翻转导致锚点跳跃 → 修复：`centered` 改回 `true`、`CollisionShape2D` position 归 `(0,0)`、脚本改用 `sprite.flip_h`（以中心轴翻转）。修复后用户确认「非常顺滑」。
  5. **Mac 按 F6**：需 `Fn + F6`，或点右上角「运行当前场景」按钮；可在系统设置勾选「将 F1、F2 等键用作标准功能键」。
  6. **找不到 Filter 设置**时兜底方案：退出 Godot → 删除 `.godot/` 缓存目录 → 重开项目强制按 project.godot 全局设置重导入。【AI 建议，未实际用到】
- **移动脚本要点**（`scripts/entities/player_character.gd`，AI 提供、用户粘贴）：`extends CharacterBody2D`，`_physics_process` 读取 `Input.get_vector(...)` 驱动 `velocity` + `move_and_slide()`，按 `_input_vector.x` 设置 `flip_h`；`_ready()` 打印 `Player ready at %s`。
