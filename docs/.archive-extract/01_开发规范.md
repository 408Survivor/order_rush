## 1. 开发规范

### 1.1 目录结构（用户要求严格执行，AI 落实为具体结构）

用户要求遵循 Godot 推荐结构、禁止根目录堆文件【用户】。AI 定稿的目录结构【AI】：

```
order_rush/
├── .git/  .gitignore  project.godot  README.md
├── scenes/            # .tscn 场景
│   ├── levels/  entities/  ui/  props/
├── scripts/           # .gd 脚本
│   ├── autoload/  entities/  systems/  ui/  utils/
├── assets/
│   ├── art/{characters,items,environment,ui,effects}/
│   ├── audio/{bgm,sfx,ambience}/
│   └── fonts/
├── resources/
│   ├── data/          # 菜品/角色/关卡配置 .tres
│   └── themes/
├── archive/
│   └── generations/   # AI 生成存档（见 1.5）
└── docs/              # 全部项目文档（纳入 Git）
```

文件归位铁律【AI，经用户认可】：`.tscn`→`scenes/`、`.gd`→`scripts/`、`.png`→`assets/art/`、根目录禁止堆文件。

### 1.2 命名规范【用户提出，AI 收录进手册速查表】

- 场景文件：PascalCase（如 `Microwave.tscn`、`MainScene.tscn`）
- 脚本与变量：snake_case（如 `microwave.gd`、`order_manager.gd`）
- 信号名：过去分词或动宾结构（如 `order_completed`、`item_picked_up`）
- 常量：UPPER_SNAKE_CASE
- 最终素材文件名：复制进 `assets/art/` 时不带版本/解释字样【用户明确要求】，如 `player_chef_idle.png`、`customer_office_waiting.png`

### 1.3 代码注释与文档【用户要求】

- 每个脚本顶部注释说明文件职责；每个函数注释输入/输出/副作用
- 复杂算法（优先级排序、时间裕度计算）逐行注释
- 禁止魔法数字：所有数值（加热时间 3 秒、耐心值 30 秒）必须定义为常量或 `@export` 导出变量

### 1.4 Git 规范

- 每个 Phase 完成 = 一个可提交里程碑；每个 commit 必须可运行【用户要求，AI 强化】
- commit message 用 Conventional Commits 简化版：`feat/fix/asset/docs/chore`【AI 建议】
- Phase 结束打 tag：`git tag -a pX -m "Phase X 完成"`【AI 建议】
- Phase 0 的 commit 节点：`p0: art style baseline`；Phase 1 共 10 个 commit 节点（初始化→玩家移动→手持物品→微波炉→顾客→完整订单循环→调试面板→素材→验收合并 `p1: core gameplay loop`）【AI 规划】

## 2. 设计决策（全部来自用户初始设计案）

- **游戏定位**：2D 俯视角预制菜小餐馆经营模拟，融合《飞机大厨》高频操作爽感 +《杯杯倒满》经营深度与 PC 键盘操作；"堂食+外卖"双线程
- **预制菜三级出餐**：L1 即热约 6 秒（冰柜取包→撕→微波炉→装盘）；L2 即烹约 14 秒（多料包炒锅现做）；L3 现做+备菜约 25 秒（开店前备餐模式做凉菜如拍黄瓜，营业中现做高价菜如小炒牛肉）
- **外卖调度**：订单到达时间 ≠ 骑手到达时间；每单显示"时间裕度"（骑手 ETA − 制作时间），红黄绿蓝四色紧急度
- **经营循环**：单局 7–10 分钟模拟一天；每日结算 = 收入 − 进货费 − 电费 − 房租
- **操作**：WASD/方向键移动，空格或 E 交互，手持物品一次一件
- **每单收入公式**：菜品基础价 + 打包费 + 平台补贴 − 平台扣点(基础 20%) + 好评奖励 − 差评罚款
- **每日成本**：食材成本(按售出量) + 固定房租 + 水电燃气(按设备使用次数) + 耗材费
- **肉鸽卡牌**：口碑值打烊抽卡；五流派——走量流（满减单价-15%单量+30%、冲单每10单+50金）、品质流（L3售价+40%、打包费翻倍）、外卖专精（扣点-8%、超时罚减半）、堂食专精（熟客20%免看菜单）、成本流（食材-15%、水电-30%、耗材-20%）
- **局外成长**：6 个人物（快手主厨制作-15%、打包达人、精明老板扣点-5%、现炒高手L3+20%、外卖老手骑手容忍+5秒、社交达人小费+100%）；设备升级（微波炉功率/双腔、冰柜、炒锅、封盖机、外卖打印机、保温柜、排烟）；店铺装修
- **难度曲线**：Day 1（5单全堂食全L1）→ Day 7（18单、并发5、70%外卖、间隔缩短50%）；Week 2+ 订单量每周+20%、并发上限6、特殊事件（设备故障/断货/天气/探店博主）
- **招牌菜系统**：每日开店强制设 1 个；店铺 Lv.1/2/3 上限 1/2/3 个；效果售价+30%、点单率+20%、小费+50%、外卖补贴+5金；连续 3 天制作-10%、7 天-20%
- **平台路线**：itch.io 首发付费验证（¥6-15）→ TapTap 免费测试 → Steam 正式发售
- **未来**：2-4 人多人合作（备餐/烹饪/打包/外卖分工）

## 3. 技术细节

- **引擎**：Godot 4.4.x + GDScript（用户有 Python 基础）【用户选定】
- **美术**：AI 生成，工具优先级即梦 > 豆包 > 可灵【AI 建议】；实际用**即梦"图片 5.0 Lite"模型**，参数 1:1、2048×2048、风格化 75%、每次 4 张【用户实际操作确认】
- **音频**：SunoAI（BGM）+ PopPop AI/freesound（音效）；用 AudioBus 分轨管理【用户/AI】
- **导入规范**：AI 图片导入 Godot 统一设 **Filter: Nearest**【用户要求】
- **风格锁定结论**：扁平矢量插画、Q 版头大身小、暖色高饱和、清晰粗描边、透明背景、左上光源
- **关键提示词经验**【对话实测，AI 记录进文档】：
  - `top-down perspective` 在即梦会生成**正面正视图**（失败案例，001 批次）
  - 有效结构：`Overhead view, bird eye view from directly above, looking straight down from ceiling, [主体描述], [统一风格后缀]`（002 批次起成功）
  - 即梦无负面提示词输入框，排除要求用 `without 3d render, without realistic style, ...` 融入正面提示词
  - 顾客类实际是"斜上方约 45° 俯视能看到后脑勺"，非纯 90°，但游戏可用（需看到背部衣服区分身份）
- **Phase 1 代码框架**【AI 在开发手册中给出，尚未实施】：5 份脚本——`GameStateManager.gd`（autoload 全局订单状态）、`player_character.gd`、`microwave.gd`（Idle/Heating/Done 状态机）、`customer.gd`（Entering→Waiting→Eating→Leaving）、`debug_panel.gd`（F1 切换）；输入映射 WASD/空格/F1
- **调试约定**：F1 切 Debug 面板显示 OrderManager 状态/活跃订单/设备占用；`print_rich`/`print_debug` 输出关键状态【用户要求】
- **里程碑总览**【AI 规划，12-16 周】：P0 美术锁定(W1) → P1 核心循环(W2-3) → P2 订单系统(W4-5) → P3 经济结算(W6) → P4 外卖调度(W7-8) → P5-P9 设备升级/卡牌/多菜品难度/角色/Polish(W9-16)
- **即梦 CLI**：官网提供 `curl -s https://jimeng.jianying.com/cli | bash` 安装 `dreamina` 命令行工具；对话时**未安装**，决定先用网页版、批量生成阶段再装【AI 建议，用户未执行安装】
