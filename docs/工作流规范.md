# 爆单时刻 — 会话工作流规范

> 本文件定义了开发者与 Kimi 之间的会话交接流程。
> 所有会话的开始和结束都应遵循此规范，确保上下文无缝传递。

---

## 1. 会话启动（开工）

### 标准启动语

```
开始今天的开发，请阅读 ReadmeForAgent.md。
```

### Kimi 执行顺序

1. 阅读 `ReadmeForAgent.md`（加载项目上下文）
2. 阅读 `docs/进度看板.md`（确认最新状态）
3. 检查 `assets/art/` 确认已有素材（如有需要）
4. 根据 ReadmeForAgent.md 中的"待办事项（Next）"推进任务

### 其他启动场景

| 场景 | 你说 |
|------|------|
| 标准开工 | **"开始今天的开发，请阅读 ReadmeForAgent.md。"** |
| 紧急求助 | **"紧急求助：[具体问题]，请优先处理。"**（Kimi 跳过上下文加载，先解决问题） |
| 回顾状态 | **"回顾一下项目当前状态。"**（Kimi 只总结，不推进任务） |
| 继续上次 | **"继续上次的工作。"**（Kimi 从上次中断点恢复） |

---

## 2. 会话结束（收工）

### 标准收工语

```
同步到文件，我要休息了。
```

### 更简短的替代语

```
收工
```

### Kimi 执行顺序

1. 阅读当前 `docs/进度看板.md`，确认最新状态
2. 阅读当前 `ReadmeForAgent.md`，确认已有内容
3. **更新 `docs/进度看板.md`**：
   - 最后更新日期
   - 总体进度百分比
   - 执行状态表中的任务状态
   - 最近活动记录追加新条目
   - 待办/阻塞项更新
4. **更新 `ReadmeForAgent.md`**：
   - 当前阶段与进度
   - 已生成素材列表（如有新增）
   - 待办事项（Next）更新
   - 本次会话关键决策/发现（新增经验记录）
   - 最后更新日期
5. 更新 TodoList（如有使用）
6. 向用户输出**一句话总结**：今天完成了什么，明天第一步做什么

### 其他结束场景

| 场景 | 你说 | Kimi 处理 |
|------|------|----------|
| 标准收工 | **"同步到文件，我要休息了。"** | 完整更新所有文档 |
| 简短收工 | **"收工"** | 同上 |
| 中断（不同步） | **"我要中断，先不同步。"** | 记录简短中断摘要，不更新文件 |
| 快速确认 | **"确认一下当前进度。"** | 只读取进度看板，不更新文件 |

## 4. 文件更新优先级

当用户说"收工"时，Kimi 按以下优先级更新文件：

| 优先级 | 文件 | 内容 |
|--------|------|------|
| P0 | `docs/进度看板.md` | 日期、进度条、执行状态、活动记录、待办 |
| P0 | `ReadmeForAgent.md` | 阶段进度、素材列表、待办、经验记录、日期 |
| P1 | `README.md` | 如有重大变更（如阶段转换、新增目录） |
| P2 | `Lookme.html` | 如有新增素材图片可展示（可选） |

## 5. 一句话总结模板

Kimi 收工时应输出类似以下内容：

```
今日完成：生成顾客俯视角素材（003批次），已选中 v1 并复制到 assets/art/characters/。
明日第一步：生成微波炉俯视角（004批次），提示词已准备就绪。
```

## 6. 常见问题

### Q: 如果我只做了一点点工作，也要说"收工"吗？
**A**: 是的，无论完成多少，只要会话结束，就说"收工"。Kimi 会记录进度，哪怕只是"开始生成但未完成"也是有效状态。

### Q: 如果会话中断了（我忘记说收工），下次怎么办？
**A**: 下次直接说 **"继续上次的工作"**，Kimi 会从对话历史中恢复上下文。如果历史丢失，Kimi 会阅读 `ReadmeForAgent.md` 和 `进度看板.md` 作为 fallback。

### Q: 我可以一次完成多个任务再收工吗？
**A**: 当然可以。收工只代表"当前会话结束"，不限制任务数量。Kimi 会记录所有完成的任务。

### Q: 如果我想在收工前确认一下更新内容，怎么说？
**A**: 说 **"预览一下要同步的内容"**，Kimi 会列出将要更新的文件和改动点，等你确认后再执行。
